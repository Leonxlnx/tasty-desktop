# Legacy release 0.9.0

This release delivers a larger interface redesign, truthful Kimi Code CLI `0.29.1` runtime controls, and durable follow-up for finite background work.

## Highlights

- Rebuilds the desktop as one continuous graphite workspace instead of separate dark cards.
- Refines the project sidebar, conversation, composer, and work rail with clearer typography, spacing, borders, hover states, and reduced-motion behavior.
- Keeps a chat pinned to its latest activity while the reader is already at the bottom, preserves position after the reader scrolls up, and offers an explicit **Jump to latest** control.
- Shows `Low`, `High`, `Max`, and future reasoning effort values only when the active Kimi runtime offers them. Legacy `Thinking On` is shown as runtime-managed `Default`, not mislabeled as `Max`.
- Discovers real user and project skills from Kimi and Agents directories. Confirmed local installation accepts only validated sources inside the active workspace and never overwrites an installed skill.
- Projects real Kimi `Agent` calls and persisted background tasks into the Agents rail instead of presenting shortcut prompts as running agents.
- Monitors finite Kimi tasks that request automatic notification, survives a local server restart, and queues an at-least-once follow-up so Kimi can inspect the output and report the verified result.
- Bounds liveness-critical renderer requests, preserves event reconciliation after a timeout, and makes explicit Windows recovery terminate the old sidecar process tree before replacement.
- Terminates the complete app-owned Windows sidecar tree when the desktop exits.

## Safety boundaries

- Kimi Code CLI remains authoritative for accounts, models, effort values, permissions, sessions, agent execution, commands, skills, MCP behavior, and subscription quota.
- Background monitoring reads only a bounded task record and output log belonging to the matching Kimi session. It expires after 24 hours and does not monitor long-lived tools that disable their timeout.
- Crash recovery provides at-least-once follow-up. It does not claim exactly-once delivery to an external model or process.
- Skill installation rejects traversal, symlinks, invalid manifests and names, oversized bundles, and existing destinations.

## Verification

Release qualification covers the public-source guard, server and web typechecks and tests, Rust formatting and tests, production service builds, bundled-server startup, installer metadata, loopback liveness, file hashes, and `git diff --check`.

The supervised verification boundary is local shell tests and builds only. No Codex in-app browser, browser MCP, Chrome control, screenshot capture, or browser-based visual QA is used or claimed.

## Install

Download `Kimi-Code-Desktop-0.9.0-x64-setup.exe` from the GitHub release and run it on Windows 10 or Windows 11.

The official installer, updater signature, update manifest, and SHA-256 checksums are produced only by the tagged GitHub Actions release workflow. A locally built unsigned installer is for development verification and must not replace the signed release asset.

Windows SmartScreen may show an unrecognized-publisher warning because Microsoft Authenticode signing is not configured yet. Tauri updater signatures remain enabled and are separate from Authenticode.
