# Tasty 0.10.0

Tasty 0.10.0 turns the former Kimi-only desktop client into a multi-provider coding agent harness while preserving existing local chats, settings, and updater trust.

## Highlights

- Rebranded the native app, packages, server identity, documentation, release artifacts, and GitHub repository as Tasty
- Added Kimi, OpenAI Codex, Anthropic Claude, and Cursor provider onboarding with CLI-owned sign-in and sign-out
- Added official Codex app-server and Claude stream-json adapters alongside Kimi and Cursor ACP
- Added `/goal`, `/goal clear`, and nested `/side` chats
- Added inspectable Codex subagent transcripts with parent-thread authorization
- Added a provider picker and runtime-driven model, reasoning, and permission controls
- Added a compact Kimi quota footer and a softer connected sidebar surface
- Added plain-language live work, compact tool rows, automatic completed-work collapse, and summary reports
- Reduced long-chat work to linear grouping and initially renders only the newest 60 turns
- Added provider, architecture, security, and T3 Code research documentation

## Upgrade compatibility

The Windows application identifier, single-instance mutex, and preference key remain compatible with 0.9. Existing local data and updater identity are preserved. The installed product name and future installer artifacts are Tasty.

## Security

- Provider credentials stay in the official provider CLI stores.
- Subagent inspection is limited to receiver thread IDs linked by the parent runtime event.
- The loopback server, workspace path boundary, local preview boundary, and signed updater checks remain enforced.
- The `glib` advisory in Cargo.lock is absent from the supported Windows target graph and is documented as not used in GitHub Dependabot.

## Verification

Release candidates must pass the public-source guard, all typechecks and tests, service builds, Rust formatting, Windows target dependency checks, and an unsigned local NSIS packaging build. Installation and restart require explicit confirmation after all active tasks finish.
